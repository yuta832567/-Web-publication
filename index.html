SECTION 01
なぜ「環境整備」から始めるのか

「メモはチャットに書けばいい」「ファイルはデスクトップに置けばいい」——それでも始められます。 でも作業が少し増えると、必ずこの壁にぶつかります。

😰 環境整備なし — よくある混乱
❌「あのプロンプト、どこに書いたっけ？」と履歴を延々さかのぼる
❌コードを直したら動かなくなった。元に戻せない
❌ファイル名が「最終_v2_修正済_本当の最終.html」になる
❌PCが壊れたら全データが消える。控えがない
❌別の端末で作業しようとしたら同じファイルがない
✅ 環境整備あり — こうなる
✅プロンプトはノートに体系的に保存。いつでも検索・再利用
✅変更履歴を管理。いつでも元の状態に戻せる
✅「最新版」が明確で迷わない
✅クラウドに同期済み。PCが壊れてもデータは安全
✅どの端末からでも同じ環境で作業できる
💡 ツールを使う目的は、つまるところ4つ
①保存する（なくさない）／②管理する（整理・検索できる）／③戻せる（変更履歴を残す）／④共有・連携できる（他の場所・人とつながる）。 どのツールも、この4つのどれかを助けるためにあります。名前を覚えるより「何の役割か」で捉えると迷いません。

守り ①
APIキーは「環境変数」で隠す（最重要）

APIキーは、外部のAIサービスを使うための合鍵です。 これがコードに直書きされたまま公開されると、第三者に拾われ、勝手に使われて高額課金される事故につながります。 対策は、キーをコードに書かず環境変数として預けることです。

❌ やってはいけない（直書き）
// コードの中に鍵がむき出し const key = "sk-abc123_本物の鍵"; fetch(api, { headers: key });
GitHubに上げた瞬間に世界中から見える状態に。探索プログラムに拾われ、数分で悪用されることもあります。
✅ 正しいやり方（環境変数）
// 鍵は外（サービス側）に預ける const key = process.env.API_KEY; fetch(api, { headers: key });
実際の鍵は .env ファイルや公開サービスの管理画面に登録。コードには「鍵の名前」だけが残り、本体は見えません。
⚠️ よくある事故：GitHubにキーを上げてしまう
.env ファイルは .gitignore に登録し、履歴に含めないのが鉄則です。もし誤って公開してしまったら、そのキーは即座に無効化（再発行）してください。一度ネットに出た鍵は「もう漏れたもの」として扱います。
📎 ありがちなシナリオ
「動いたから」と OpenAI のキーを直書きしたまま GitHub で公開 → 数時間後に身に覚えのない高額請求、というケースは実際に多く報告されています。公開リポジトリの鍵は探索プログラムに数分で拾われる前提で、最初から環境変数に入れるのが安全です。
守り ②
HTTPS — 通信を暗号化する

HTTPSは、利用者とサイトの間の通信を暗号化して、途中で盗み見られないようにする仕組みです。鍵マークのついた https:// がそれです。

✅ 朗報：主要サービスでは標準で有効
Vercel・Netlify・Cloudflare Pages などでは、HTTPSは初めから設定済みです。独自ドメインを追加した場合も、証明書はサービス側が用意してくれます。特別な作業はほぼ不要で、まず安心してよいポイントです。
⚠️ 自前サーバーを立てる場合は別
AWSのEC2などで自分でサーバーを構築する場合は、SSL証明書（エスエスエル証明書）の設定を自分で行う必要があります。Let's Encrypt（レッツ・エンクリプト）などで無料発行できますが、ひと手間かかります（→ 規模が大きくなってからの話：タブ6）。

🛡 OpenAI等の「利用上限」を設定する（課金事故の防止）

従量課金のAIは、設定ひとつで使いすぎを防げます。最初に上限を入れておくだけで、想定外の高額請求をほぼ回避できます。手順はサービス共通でほぼ同じです。

1

請求設定を開く

管理画面の「Billing（請求）」→「Limits（上限）」を開きます。

2

上限額を決める

月に使ってよい上限金額（ハードリミット）を設定。例：月50ドルなど無理のない額に。

3

通知を入れる

上限の手前でメール通知が届くよう設定（例：8割で警告）。

4

キーを分ける

用途ごとにAPIキーを分け、不要になったキーはすぐ無効化します。

⚠️ 「上限なし」が最大のリスク
上限を設定していないと、キーが漏れた場合や処理が暴走した場合に青天井で課金されます。金額の正確な画面項目は変わることがあるため、各サービスの公式ヘルプもあわせて確認してください。

🤔無料で公開できますか？費用はどれくらい？
▼
最初は無料で公開できます。Vercel・Netlify・Cloudflare Pages はいずれも個人利用の無料枠があります。データベース（Supabase・Firebase）にも無料枠があります。アクセスが増えたり商用利用したりすると有料プラン（月数千円〜）が必要に。まず無料枠で始め、必要になったら有料へ移行するのが定番です（詳しくはタブ6）。
🤔AIが作ったコードをそのまま公開できますか？
▼
多くの場合できますが、確認が必要です。HTML1枚ならNetlifyにドラッグで即公開。Next.jsならGitHub経由でVercel連携。ただしAPIキーを使う場合は環境変数で隠す必要があり（タブ5）、ログインやDB機能には別途セットアップが必要です（タブ4）。
🤔Next.js と Astro、どちらで作ればいい？
▼
ページ中心ならAstro、アプリ機能があるならNext.jsと考えてください。Astroは表示が速く静的ページが得意。Next.jsはログイン・DB連携・APIに強い。AIがNext.jsで出力したら、そのまま使うのが最も効率的です。
🤔独自ドメイン（例：mysite.com）は使えますか？
▼
はい、どのサービスでも設定できます。ドメインは年数百〜千円程度で取得でき、管理画面で追加するだけでHTTPSも設定されます。まずは無料のサブドメイン（例：myapp.vercel.app）で動作確認し、後から独自ドメインに切り替えるのがおすすめです。
🤔最初から AWS を使うべきですか？
▼
いいえ、ほとんどの場合は不要です。個人〜中規模ではVercelやSupabaseで十分まかなえます。AWSは柔軟ですがむずかしく、運用の手間も増えます。実際に上限や不便にぶつかってから移行しても間に合います（タブ6）。
🤔セキュリティで最低限やるべきことは？
▼
まずはAPIキーを環境変数で隠すこと。これが最重要です。加えて、HTTPSの確認、ログインが必要な画面の保護、個人情報を集めすぎないこと。タブ5の「公開前チェックリスト」を一度なぞれば、大きな事故はほぼ防げます。
ROADMAP
学習ロードマップ — 次に何を覚えるか

「全部一度に」と思わないでください。段階を踏むことが最短ルートです。

1
STAGE 01 — まずここから
HTMLのLPをNetlifyで公開する
AIにHTMLを出力してもらい、Netlifyのドラッグ&ドロップで公開。「作る→公開する」を体で覚えるのが最優先。完成度より完了を目指す。
2
STAGE 02 — 次のステップ
GitHubと連携してVercelで公開する
GitHubにコードを置き、Vercelと連携。更新するたびに本番へ反映される仕組みを体験する。AI開発の速度が一段上がる。
3
STAGE 03 — 応用
Supabaseでログイン・保存を追加
ユーザーが登録・ログインでき、データを保存できるアプリへ。ここまで来ると「本格的なWebアプリ」と呼べるものが作れる。
4
STAGE 04 — 発展
独自APIの構築・規模の拡張
Python/Node.jsで独自の裏側処理を作成。複数ツールの組み合わせや大規模運用を視野に。Render・Railway・AWSも選択肢に入る。
